# 機能一覧

---

## 0️⃣ 前提定義

| 項目 | 内容 |
| --- | --- |
| 対象ユーザー | `PlatformAdmin`、`TenantAdmin`、`HackathonOrganizer`、`Sponsor`、`Judge`、`Hacker` |
| 提供価値 | Tenant 配下に複数の Hackathon を持ち、招待 URL と参加パスワードで参加を管理しながら、アプリ内スカウトとメール通知を安全に運用できる状態をつくる |
| コア体験 | `PlatformAdmin` が Tenant を立ち上げ、`TenantAdmin` が Hackathon と Sponsor 範囲を管理し、`HackathonOrganizer` が招待と Hackathon 単位設定を回し、送信者がアプリからスカウトを送り、出場者がメールで受け取る |
| ロール原則 | 管理ロールは `PlatformAdmin` / `TenantAdmin` / `HackathonOrganizer`、送信ロールは `Sponsor` / `Judge` として分離する。同一ユーザーの兼務は許容する |
| 成功指標 | MVP では「Tenant 作成完了率」「招待参加完了率」「メール認証完了率」「スカウト送信成功率」「スポンサー閲覧範囲設定の反映正確性」を主要指標とする |

# 1️⃣ 機能カテゴリ設計

## 【カテゴリA：招待・認証基盤】

| # | 機能名 | 概要 | ユーザー価値 | 優先度 | 備考 |
| --- | --- | --- | --- | --- | --- |
| A-1 | メール認証付きアカウント登録・ログイン | 登録時にメール認証を行い、認証済みユーザーのみ利用できるようにする | なりすましを抑え、通知先メールの正当性を担保できる | 🔴 P0 | MVP 対象 |
| A-2 | ハッカソン参加用招待 URL + 参加パスワード | `Hacker` と `Judge` が Hackathon 単位で参加できる導線を提供する | 手動登録なしでイベント参加を進められる | 🔴 P0 | 有効期限付き招待を前提 |
| A-3 | スポンサー参加用招待 URL + 参加パスワード | `Sponsor` が Tenant 単位で参加できる導線を提供する | スポンサー招待を運営側で簡単に回せる | 🔴 P0 | 有効期限付き招待を前提 |
| A-4 | ロール / スコープ切替 | 複数ロール・複数スコープを持つユーザーが利用中のコンテキストを切り替えられる | 同一ユーザーが `TenantAdmin` / `HackathonOrganizer` / `Sponsor` / `Judge` を兼務しやすい | 🔴 P0 | MVP 対象 |
| A-5 | メール再送・パスワード再設定 | 未認証ユーザーへの再送、ログイン不能時の復旧導線を提供する | 認証離脱を減らし、運用負荷を下げる | 🟡 P1 | 初期運用で必要になりやすい |
| A-6 | ユーザープロフィール管理 | 表示名、所属、連絡先などを更新できるようにする | スカウト文面や通知先の整備がしやすくなる | 🟢 P2 | MVP 後で十分 |

## 【カテゴリB：スカウト送受信】

| # | 機能名 | 概要 | ユーザー価値 | 優先度 | 備考 |
| --- | --- | --- | --- | --- | --- |
| B-1 | アプリ内スカウト作成・送信 | `Sponsor` または権限を持つ `Judge` がアプリからスカウトを入力し送信する | 外部ツールなしで正式なスカウトを一元管理できる | 🔴 P0 | MVP の中心機能 |
| B-2 | スカウトメール通知 | 送信されたスカウトを `Hacker` の登録メールアドレスへ通知する | 出場者が見落としにくく、アクションにつながりやすい | 🔴 P0 | MVP 対象 |
| B-3 | スカウト受け取り可否設定 | 出場者がスカウト受信の opt-in / opt-out を設定できる | 不要な連絡を避けつつ、許諾済み相手にだけ送れる | 🔴 P0 | MVP 対象 |
| B-4 | スカウト一覧・ステータス管理 | 送信済み、受信済み、状態別にスカウトを確認できる | 送信者・受信者ともに状況を追いやすくなる | 🟡 P1 | MVP 後の運用改善 |
| B-5 | スカウトテンプレート | よく使う文面を保存し再利用できるようにする | 送信作業を短縮し品質を揃えやすい | 🟢 P2 | 運用最適化向け |

## 【カテゴリC：Platform / Tenant / Hackathon 運用】

| # | 機能名 | 概要 | ユーザー価値 | 優先度 | 備考 |
| --- | --- | --- | --- | --- | --- |
| C-1 | PlatformAdmin Dashboard | `PlatformAdmin` が Tenant を管理するためのグローバル画面を提供する | プロバイダー側で Tenant 立ち上げを一元管理できる | 🔴 P0 | MVP 対象 |
| C-2 | Tenant 追加 | `PlatformAdmin` が新規 Tenant を作成できるようにする | 新しい開催団体や案件をすぐに立ち上げられる | 🔴 P0 | MVP 対象 |
| C-3 | 初期 TenantAdmin 割り当て | `PlatformAdmin` が Tenant 作成時に初期 `TenantAdmin` を割り当てられる | Tenant 作成後すぐに自走運用へ渡せる | 🔴 P0 | MVP 対象 |
| C-4 | TenantAdmin Dashboard | `TenantAdmin` が Hackathon、Sponsor、範囲設定を管理するための画面を提供する | Tenant 単位の運営を安全に回せる | 🔴 P0 | MVP 対象 |
| C-5 | Hackathon 追加 | `TenantAdmin` が Tenant 配下に Hackathon を作成できるようにする | イベント単位で参加者と設定を切り分けられる | 🔴 P0 | MVP 対象 |
| C-6 | HackathonOrganizer 割り当て | `TenantAdmin` が各 Hackathon に `HackathonOrganizer` を割り当てられる | イベント運営を委譲できる | 🔴 P0 | MVP 対象 |
| C-7 | Sponsor 招待管理 | `TenantAdmin` が `Sponsor` 向け招待の発行、有効期限設定、再発行、無効化、参加パスワード管理を行える | 協賛企業の参加導線を標準化し、期限管理もできる | 🔴 P0 | 有効期限は `5 / 7 / 14 / 30 / 60 / 90日` |
| C-8 | Sponsor 表示ハッカソン範囲設定専用画面 | `TenantAdmin` が `Sponsor` ごとに閲覧可能な Hackathon 範囲を専用画面で設定できる | スポンサーに見せる対象を安全に制御できる | 🔴 P0 | MVP 対象 |
| C-9 | HackathonOrganizer Dashboard | `HackathonOrganizer` が担当 Hackathon を管理するための画面を提供する | Hackathon 単位の運営を分担しやすい | 🔴 P0 | MVP 対象 |
| C-10 | Hackathon 招待管理 | `HackathonOrganizer` が `Hacker` / `Judge` 向け招待の発行、有効期限設定、再発行、無効化、参加パスワード管理を行える | 参加者登録の手間を大幅に減らせる | 🔴 P0 | 有効期限は `5 / 7 / 14 / 30 / 60 / 90日` |
| C-11 | Hackathon 単位のスカウト ON / OFF 設定 | `HackathonOrganizer` または `TenantAdmin` が Hackathon ごとにスカウト機能を有効 / 無効化できる | 開催方針に応じてスカウト提供有無を切り替えられる | 🔴 P0 | MVP 対象 |
| C-12 | Judge 送信権限設定 | `HackathonOrganizer` または `TenantAdmin` が Hackathon ごとに `Judge` のスカウト送信可否を設定できる | 審査方針に合わせて送信主体を制御できる | 🔴 P0 | MVP 対象 |
| C-13 | Tenant 別メール文面設定 | 件名、署名、案内文などを Tenant ごとに調整できる | ブランドや案内ルールを崩さず通知できる | 🟡 P1 | 運用要望が出やすい |
| C-14 | 監査ログ・操作履歴 | 誰がいつ設定変更やスカウト送信をしたかを追跡できるようにする | トラブル時の確認と説明責任を果たしやすい | 🟢 P2 | セキュリティ・運用向け |

# 2️⃣ 優先順位の定義基準

| 優先度 | 判断基準 |
| --- | --- |
| 🔴 P0 | これがないと MVP として「Tenant 立ち上げ + 招待参加 + スカウト送信」が成立しない |
| 🟡 P1 | MVP 後すぐに体験・運用を改善するために重要 |
| 🟢 P2 | 安定運用や効率化に効くが後続でも成立する |
| ⚪ P3 | 将来の差別化や高度化に寄与する |
